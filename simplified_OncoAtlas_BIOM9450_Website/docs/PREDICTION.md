# Predictive analysis — how it works (owner: Chris)

Predicts which of six cancer types a patient's mutation profile most resembles, using a random forest trained on TCGA PanCancer Atlas data. **Educational research tool, not a diagnosis.**

## Files owned by the predictive-analysis section (please don't edit without asking Chris)

| File | Purpose |
|---|---|
| `predict.php` | Run prediction page: choose patient or preview a TSV, see the chart, save |
| `api/model_input.php` | AJAX GET: a patient's mutation rows from the `ModelInput` view |
| `api/save_prediction.php` | AJAX POST: server recomputes the prediction, checks it, saves it in one transaction |
| `app/model_predictor.php` | PHP copy of the model (features + forest) and the transactional save function |
| `assets/js/predict.js` | JS copy of the model: TSV parsing, features, forest traversal (runs in the browser) |
| `assets/js/predict_page.js` | Page behaviour: AJAX calls, interactive charts, save button |
| `assets/css/predict.css` | Styles for the prediction page |
| `assets/model/rf_model.json` | Exported model; generated by `biom_project/train_tcga.py`, never edit by hand |

Small hooks added to shared files: a sidebar link (`app/layout.php`), a **Run prediction** button (`patient.php`), the "model connected" banner (`predictions.php`), a linked-mutation count (`prediction.php`), and an optional private `config/config.local.php` override (`config/config.php`).

**Things my code depends on:** the function names in `app/bootstrap.php`, the `ModelInput` view, and the column names of `CancerType`, `Prediction`, `PredictionScore`, `PredictionMutation` and `Feedback`. The six `CancerType.StudyCode` values must stay `laml, lgg, brca, lihc, paad, prad`.

## User flow

1. Oncologist/researcher opens **Run prediction** (or the button on a patient's page).
2. Choose a patient. `predict_page.js` loads the saved rows from `api/model_input.php` (AJAX).
3. `predict.js` builds 331 features and runs the 60-tree forest **in the browser**. It then shows the result: an interactive bar chart of all six scores, input summary, mutation spectrum, and warnings (low margin, whether the patient was in the training set, whether the predicted type matches the recorded diagnosis, no model genes found).
4. **Save** sends the patient ID, model version and browser scores to `api/save_prediction.php`. The server:
   - checks login, role, CSRF token and patient;
   - reloads the rows from MySQL and recomputes the scores in PHP;
   - refuses to save if the model version or any score differs from the browser result (logged as `PREDICTION_REJECTED`);
   - in **one transaction**, inserts `Prediction`, 6 × `PredictionScore`, and one `PredictionMutation` link per input mutation row. It first checks that every linked row belongs to that patient;
   - logs `CREATE_PREDICTION` and returns the URL of `prediction.php?id=…`.
5. On `prediction.php` the user submits feedback (accurate / not accurate / cannot assess + comment), which is stored in `Feedback` against that prediction.

Alternatively, a TSV file can be **previewed** (not saved). To save a prediction for a file, import it on the patient's record first with Import mutations, then predict from the saved profile. This keeps every saved prediction linked to real `SampleMutation` rows.

## The model

- Training script: `biom_project/train_tcga.py`; outputs in `biom_project/model_output_tcga_v2/` (v1 kept in `model_output_tcga/`).
- Data: 2,745 TCGA patients across 6 cancer types (AML, lower-grade glioma, breast, liver, pancreas, prostate). Split 80/20 by patient, stratified: 2,196 for training, 549 held out for testing.
- Features (331): log(1 + number of mutations); proportions of 6 strand-normalised SNP types + indel + other; proportions of 21 standard MAF variant classes + other; 0/1 indicators for the 300 most frequently mutated genes.
- Models compared with 5-fold CV (macro-F1): majority baseline, decision tree, random forest, RBF SVM. Random forest was best by CV.
- The **website runs a smaller forest** (60 trees, depth ≤ 10) so the JSON stays small (0.4 MB). Its held-out results are **79.0 % accuracy and 0.778 macro-F1**. The full forest (81.2 % accuracy, 0.800 macro-F1) is reported for comparison only.

v2 fixes compared with v1: (1) fixed variant-class vocabulary instead of learning it from all patients; (2) top-gene selection refitted inside each CV fold; (3) de-duplication by genomic position so distinct mutations in one gene are kept.

To retrain: `cd biom_project` → `python train_tcga.py`. The script copies the new `rf_model.json` here automatically. Then re-run the tests below. If the features change, update `predict.js` and `model_predictor.php` together.

## Limitations

- Scores are averaged tree outputs, not calibrated clinical probabilities. The model can only choose among these six cancer types.
- ~80 % of the demo database patients were in the training set, so their predictions look better than they would on new data (the page flags this). Only 60 demo patients are held-out test patients.
- Mutation count and non-coding annotation proportions can reflect how each TCGA study was sequenced and processed, not just biology. Feature importance shows association, not causation.
- Feedback is stored for review; the model is **not** retrained automatically from it.
